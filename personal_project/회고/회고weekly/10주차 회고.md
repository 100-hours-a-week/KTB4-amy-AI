## 3. 진행 상세

### FastAPI 세션 + Human-in-the-Loop (완료)
- 세션 도입과 HITL 흐름을 마무리함.
- `interrupt` 시 `result`가 리스트로 반환되는 이유는 병렬 접근 대비. 현재는 입력이 하나라 인덱스 `0`으로 고정했으며, 추후 병렬화 시 수정 필요.
- `config`를 `state`와 분리 선언하는 이유는 둘의 기능이 다르기 때문. 딕셔너리 형태인 것은 확장성 목적(메타데이터 등도 이쪽에 포함).
- 상태 확인용 GET 라우트를 임시로 둔 상태이며, 수업 중 언급된 `auth` 도입을 검토 여지로 남김.

### Agent 도입 검토 (보류)
- 신규 기능을 추가하기보다 기존 기능을 tool calling으로 전환하는 방향을 검토.
- 도구화 후보로 web search, search 노드를 지목(그래프의 주요 분기점이자 LLM의 판단 요소라는 이유).
- 다만 실제로 만들어 보니 도구화할 만한 대상이 마땅치 않고 답변 품질 향상도 기대하기 어렵다고 판단 → agent를 후순위로 미루고 목차 생성으로 전환.

### FR-02 목차 생성 (진행 중)
- `pymupdf`의 `get_toc()`로 챕터 추출 경로 구현 완료. PPT→PDF는 챕터가 자동 생성되고 원본 PDF는 정상 챕터가 들어오므로 판별을 LLM에 맡기는 방향으로 정리.
- TOC가 없는 경우를 대비해 폰트 크기·타입 정보를 순회해 목차를 추출하는 로직 시도(`collections.defaultdict`로 0 초기화, 크기가 같은 경우를 위해 폰트 정보까지 포함).
- 폰트 정보 비교로 본문(최다 등장 폰트)을 찾고, 그와 다른 텍스트를 추출해 목차를 만드는 LangChain 도입.
- 서브 챕터 생성 실패. 원인은 텍스트가 쪼개진 상태로 전달되는 것으로 추정.
- 코드 가독성이 떨어진 상태에 대한 스스로의 불만족 기록.

### FR-05 개념 설명 (착수·설계)
- 청킹을 유지할지 목차 기준으로 다시 나눌지 검토. 챕터 단위 출력 시 LLM이 유지할 메모리가 커질 우려가 있어 청킹은 유지하되, 청킹 데이터와 목차를 연결하는 방법을 고민.
- 챕터 스키마 정의: `title`, `page`, `level`.
- 부모-자식 청킹을 검토했으나 검색·반환 구조와 프롬프트가 크게 바뀌는 문제가 있어 채택하지 않음.
- 절충안 확정: 부모-자식 청크 대신 **챕터를 생성해 메타데이터에 삽입**. 이로써 FR-02와 FR-05를 연결하는 문제도 함께 해소.
- 청킹 로직 확정: `데이터 → 전처리 → 1회 순회하며 판별 → (제목이면 목차에 추가 / 본문이면 300자 청킹 + 직전 제목을 메타데이터로 부착) → 임베딩`.

### 전처리 정비
- 내용은 그대로 두고 목차는 메타데이터에 넣는 방식으로 정리.
- 동적 청킹 대신 기존 fixed chunking 유지로 회귀.
- Document 객체의 동작을 아직 확실히 잡지 못해 이 지점에서 버그가 반복됨. 실행 파일을 바꿀 때마다 `.env` 재적용 필요.

## 4. 배운 점 / 기술 메모

- 모델 필드 선언 시 `| None = None`을 붙이면 nullable 처리됨.
- `uuid4`는 스레드 ID 등 식별자가 필요한 곳에 재사용할 만함.
- 그래프에서 넘어온 뒤 FastAPI에서 변수를 딕셔너리처럼 다루려는 습관이 나옴 → FastAPI의 데이터 흐름을 다시 정리할 필요.
- `interrupt` 결과의 리스트 반환 = 병렬 접근 대비.
- `config`와 `state`의 분리 = 기능 분리 + 확장성.
- `get_toc()`로 챕터를 받아올 수 있고, PPT 유래 여부를 LLM 판별로 흡수 가능.
- `defaultdict`로 누적 카운팅 시 0 초기화 문제 해소.
- `strip()`으로 공백 제거. `\uf07d` 같은 특수 기호는 강조 표시 가능성이 있어 일단 보류.
