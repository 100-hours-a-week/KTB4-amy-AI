## 1. 진행 상황

### 목차 기반 PDF 분할 (완료)
- `pymupdf`의 `get_toc()`를 1차 경로로 구현.
- TOC가 없을 때를 대비한 폰트 분석 fallback을 시도했으나, 본문과 폰트 크기가 같은 서브 챕터를 검출하지 못해 폐기.
- 전체 정제 텍스트를 LLM에 전달해 `Outline`/`Chapter`(Pydantic) 구조로 아웃라인을 추출하는 방식으로 전환 → 만족스러운 결과 확보.
- 계층·인덱싱 문제 해결:
  - 서브 챕터 누락(이중 삽입)은 `level` 제한(2)을 해제해 해결.
  - LLM이 목차를 번호로 나누려는 문제는 프롬프트 강화로 해결.
  - `chapter_index`는 LLM이 부여하면 중복이 발생해, 코드에서 리스트 순서로 부여.
  - 제목이 먼저 제공될 때 대챕터 인덱싱이 0으로 몰리는 문제는 `parent` 필드 추가로 해결.
- 스키마 조정: 출처 표기가 불필요해 `page` 필드를 제거하고, page 순서 기반 `cleaned_docs`에서의 위치를 기록하는 `start_index`를 도입.

## 2. 주요 기술적 의사결정

| 결정 | 배경 |
| --- | --- |
| Agent 대신 tool calling 검토 후 보류 | 도구화 대상이 마땅치 않고 품질 향상 기대가 낮음 |
| 폰트 분석 fallback 폐기 → LLM 아웃라인 추출 | 본문과 폰트 크기가 같은 서브 챕터를 검출하지 못함 |
| 부모-자식 청킹 대신 챕터를 메타데이터에 삽입 | 검색·반환 구조와 프롬프트 변경 부담이 큼 |
| `chapter_index`를 코드로 부여 | LLM에 맡기면 중복 인덱스 발생 |
| `page` 제거 → `start_index` 도입 | 교육형 챗봇에 출처 표기 불필요, 대신 위치 기록 필요 |

## 3. 주요 이슈 및 해결

| 이슈 | 해결 |
| --- | --- |
| 서브 챕터 생성 실패 | 텍스트 분할이 원인 → LLM 아웃라인 추출 방식으로 전환 |
| 서브 챕터 누락 / 인덱스 중복 | `level` 제한 해제, `parent` 필드 추가, `chapter_index` 코드 부여 |
| 인덱스가 리스트 범위 초과 | `enumerate` join으로 새 파일 구성 + 프롬프트 수정 |
