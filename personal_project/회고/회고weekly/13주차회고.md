## 2. 주요 진행 내용

### 2.1 의도 분류 로직 마감

학생의 입력을 **챕터 요청 / 질문 / 애매함**으로 자동 분류해 알맞은 흐름으로 라우팅하는 로직을 완성했습니다.

- 분류는 `Literal` 기반 structured output으로 후보를 고정해, 자유 문자열이 라우팅 키와 어긋나는 문제를 방지했습니다.
- 첫 입력부터 인터럽트 응답까지 같은 분류기를 재사용하도록 그래프를 통합했습니다.

**해결한 문제 — 애매한 답변 무한 루프**
"안녕 → 안녕하세요, 배워볼까요? → 좋아" 흐름에서 "좋아"를 Y로 인식하지 못하고 다시 분류로 돌아가 무한 루프가 발생했습니다. 원인은 인터럽트가 아닐 때 응답 처리에서 사용자 입력을 반영하지 못한 것이었고, 응답 생성 로직을 수정하고 프롬프트를 다듬어 해결했습니다.

### 2.2 PDF 업로드 + 벡터스토어 구조

**서비스 범위 결정** — 계정별 문서 관리(1:N)는 관리 요소가 많아, 우선 일회성(1:1)으로 완성하고 이후 확장하는 방향으로 정했습니다.

**전처리 함수화**
문서가 교체될 때마다 다시 실행되어야 하는 부분(문서 로딩·청킹·벡터스토어 생성)을 `build_vectorstore()` 함수로 묶어, 실행 시점을 import 시점에서 **업로드 시점**으로 옮겼습니다.

**문서 식별 방식 — 해시 채택**
같은 문서의 재업로드를 판별하기 위해 저장 경로 기준을 검토했습니다.
- 파일명: 이름이 겹치는 문서를 구분하지 못함
- 랜덤 ID: 같은 파일을 다시 올려도 동일 문서로 인식 못 함
- **파일 내용 해시**: 위 단점을 모두 해소 → 채택

벡터스토어 경로를 파일 해시로 나눠, 해당 문서의 색인이 있으면 재임베딩 없이 로드하고 없으면 새로 생성하도록 했습니다. 별도 캐시 파일 없이 벡터스토어 존재 여부 자체를 캐시로 활용했습니다.

**업로드 처리**
FastAPI `UploadFile`로 PDF를 받고, 임시 파일로 저장한 뒤 색인 생성이 끝나면 삭제하도록 구성했습니다(임베딩 완료 후 원본은 불필요).

### 2.3 챕터 설명 출력 방식 개선

기존에는 청크 단위로 설명을 출력해, 문장 주어가 잘리고 "안녕하세요, 우리는 ~를 살펴볼게요" 식으로 매 조각이 끊겨 보이는 문제가 있었습니다.

이를 **챕터 전체를 한 번에 LLM에 넣어 설명을 생성하고, `---` 마커로 나눠 순차 출력**하는 방식으로 전환했습니다. 맥락이 이어지면서도 읽기 좋은 단위로 나뉘도록 개선했습니다.

### 2.4 모델 구성

- 품질이 중요한 챕터 설명은 Claude, 가벼운 분류·질의응답은 Gemini로 분리했습니다.
- Gemini는 여러 API 키를 폴백으로 묶어, rate limit 발생 시 자동으로 다른 키로 전환되도록 했습니다.
- 분류 등 가벼운 작업은 경량 모델로 전환해 응답 속도를 개선했습니다.

### 2.5 프론트엔드 연결 (React)
- 다중 상태(노트 목록·선택·채팅)가 얽히는 UI에서 상태-화면 동기화를 프레임워크에 위임하기 위해 React로 선정했습니다.
- 업로드 → 대화 → 인터럽트 응답 흐름을 처리하는 React 프론트엔드를 연결했습니다. 첫 요청에서 발급받은 `thread_id`를 이후 요청에 유지하며, 응답 상태에 따라 입력 UI가 전환되도록 구성했습니다.

## 3. 트러블슈팅

| 문제 | 원인 | 해결 |
|------|------|------|
| 챕터 호출 후 answer가 null | 인터럽트 응답에 answer 미포함 | 인터럽트 인자에 answer 추가 |
| 질의응답 전환 시 answer가 안 비워짐 | 이전 안내 문구가 상태에 남아 계속 노출 | 안내 문구를 별도 필드(msg)로 분리, 진입 시점에 정리 |
| 질의응답 정확도 저하 | 검색 결과(Document 객체)를 프롬프트에 그대로 전달 | 본문 텍스트만 추출해 전달하도록 수정 |
| 웹 검색 동작 불가 | 검색 라이브러리 버전 변경 미반영 + 프롬프트 제약 과함 | 라이브러리 재설치, 프롬프트 완화 |
| 응답 지연 | 분류 과정에서 LLM 호출이 많음 | 경량 모델로 전환 |
| 배포 테스트 중 503 | LLM 무료 티어 일시 과부하 (코드 이슈 아님) | 모델 전환으로 회피, 폴백에 다른 모델 추가 검토 |

## 4. 배운 점

- **환경 변수 경로**: uvicorn 실행 시 작업 디렉터리가 달라져 상대 경로가 깨짐 → 절대 경로 기준으로 고정.
- **전역 변수 선언**: 함수 내부에서 전역 변수를 갱신하려면 `global` 선언이 필요. 실행 순서에 영향받지 않는 점이 인상적이었음.
- **체크포인터의 short/long-term**: 저장 기간이 아니라 **범위** 개념(대화 하나 vs 대화 전반). 영속화를 위해서는 MemorySaver → SqliteSaver 전환이 필요하다는 것을 확인.
- **폴백 라이브러리**: LLM 호출 실패 시 자동으로 다른 키·모델로 전환하는 구조를 도입.
