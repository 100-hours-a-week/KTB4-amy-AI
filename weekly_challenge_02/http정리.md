# Http (Hyper Text Trandfer protocol)
- 하이퍼 텍스트 전달 프로토콜, 구조화 된 텍스트를 전송하기 위해 사용되는 통신 규약
- 글을 뛰어 넘는 글, 즉 멀티미디어  (ex. jpg, png, html, css, audio, link)
  - text: html, css, js
  - Binary: Image(jpg, png)
- 서버와 클라이언트가 하이퍼 텍스트 문서를 정의된 규칙에 따라 문서를 전송하기 위하여 사용 (원활한 소통을 위함)
---
## HTTP MESSAGE
- 구조화된 텍스트를 전송할때 사용되는 통신 규약의 메시지 즉 통신의 기본 단위이다. (http를 통해 모든 전송이 이루어지므로, http 한번이 기본 단위가 되는것)
- 클라이언트와 서버 간 데이터 교환을 위하여 사용
- 시작줄(start line), 헤더(HTTP headers), 빈 줄(empty line), 본문(body) 로 구성
  - 시작줄(Start Line) : 요청이나 응답 상태를 나타내는 첫번째줄
  - 헤더(Header): 메시지 바디를 요약하는 헤더들의 집합(general(일반) , request/response(요청/응답), representation(대표))
    - general : 요청과 응답 공통으로 사용되는 일반적인 헤더로, 메시지 전체에 대한 정보를 제공 (캐시, 연결유지 등 설정 포함)
    - request : 클라이언트가 서버에 요청을 보낼때 함께 전송되는 헤더, 요청과 관련된것들을 설명 하며 부가적인 정보 제공
    - representation : 본문과 관련된 헤더, 데이터의 혁식, 언어, 압축 등을 나타내어 클라이언트가 데이터를 올바르게 해석하도록 도와줌
    - 헤더는 서버가 요청을 처리하기 전 필요한 정보들을 제공, 또한 헤더는 미들웨어에서 처리 가능 (ex. content-Lenght 헤더가 제공하는 값에 따라 본문의 크기를 미리파악한 뒤 너무 짧거나 길면 요청 거절)
  - 빈 줄(Empty Line) : 헤더와 본문을 구분하기 위하여 존재하는 줄
  - 본문(Body) : 데이터나 문서 등 실제 내용이 포함되어 있음(ex. HTML 문서, JSON 데이터) 
- 서버에 요청을 하거나 서버가 응답을 할때 나오는 반응 그게 http message 임
  - http requset message, 줄여서 request, 한국어로 요청
  - http response message, 줄여서 response, 한국어로 응답
  - http 대표적인 클라이언트는 브라우저
- http 뿐만 아니라 많은 메시지 구성이 헤더와 바디로 이루어져 있음

## HTTP REQUEST METHOD
- 서버가 어떤 작업을 수행하길 원하는지 알리는 방법을 정의하는 명령 규칙
- 웹 서버에게 구체적인 작업을 명확하게 지시 하기 위함
- RPC : Remote Procedure Call, 원격 함수(기능) 호출
- start line에 요청 또는 수행에 대한 성공 실패가 기록되어 있음
- 요청을 보낼때 url과 get, post, put 등의 메소드를 명시하여 서버에게 작업을 요청 하는 방식으로 사용
  - GET 메소드 : 데이터 조회를 요청할때 사용 (call 적인 조회를 할때에는 요청 파라미터 사용) 
      - 서버에게 데이터를 요구
      - 클라이언트가 추가 정보를 보내는 방법
      - 요철 파라미터를 쿼리 스트링(Query String) 형태로 URL에 포함하여 전송 (본문이 없음)
        - ex. GET/ weather?city=seoul 을 입력하면 city 파라미터 값을 받아 서울의 날씨 정보를 응답으로 보낼 수 있음
      - 어떤 리소스(데이터)를 요청하는 것이기에 변경 작업에서 사용 하지 않음
  - POST 메소드 : 서버에게 데이터를 전송할때 / 쓰기(생성)
    - get 은 본문이 들어가지 않는 형태/post 본문이 포함 (요청 바디에 데이터를 첨부하여 전송한다)
    - 서버의 상태나 데이터 변경이 가능하다
    - ex. POST/user
  - PUT 메소드
    - 리소스(데이터)를 전체 업데이트할때 사용하는 메소드
    - 요청 바디에 데이터를 첨부하여 전송
    - ex. PUT/files/1
  - PATCH 메소드 
    - 리소스(데이터)를 부분적으로 수정하거나 업데이트할때 사용하는 메소드
    - 요청 바디에 데이터를 첨부하여 전송
    - ex. PATCH/users/1
  - DELETE 메소드
    - 서버에서 리소스를 삭제할대 사용하는 메소드
    - URL에 삭제하고자 하는 리소스의 식별자를 포함하여 전송
    - 서버는 리소스 식별 이후 삭제
    - 식별자는 대체로 숫자, 문자열 혹은 두가지의 조합으로 이루어지며 리소스마다 고유해야함
      - post/123 users/123 이렇게는 괜찮지만 post/123, post/123 은 안된다. 
    - ex.DELETE/users/1

## HTTP STATUS CODE (무조건 암기)
- 요청의 처리 상태를 나타내는 코드
- 통신 결과를 웹 서버가 클라이언트에게 명확히 전달하기 위하여 사용
- 요청 처리 결과를 나타내는 http 상태 코드를 응답 메시지의 헤더에 포함시켜 클라이언트에게 전송하는 방식으로 사용
- 번호대
  - 1xx: 정보 메시지
  - 2xx: 성공
  - 3xx: 리다이렉선 (도착 주소 재지정)
  - 4xx: 클라이언트 오류
  - 5xx: 서버 오류
- 중요 번호
  - 200: 성공
  - 201: 성공, 새로운 리소스 생성
  - 202: 요청을 수신했지만 처리 할 수 없었음 (서버가 요청을 처리하고 있거나 다른 프로세스가 처리중인 경우)
  - 204: 헤더는 유효하나 요청에 대해 보내줄 수 있는 내용이 없음
  - 400: 잘못된 문법으로 인해 서버가 요청을 이해할 수 없음 (Bad Request)
  - 401: 인증되지 않은 접근
  - 403: 인가되지 않은 접근
  - 404: 요청받은 리소스를 찾을 수 없음
  - 429: 지정된 시간 안에 너무 많은 요청을 보냄
  - 500: 서버가 처리 방법을 알 수 없음 (Internal Server Error, 내부 서버 문제)
  - 501: 요청 방법이 서버에서 지원되지 않음
  - 503: 서버가 요청을 처리할 준비가 되지 않았음 (일시적인 불가능)
- [그외 상태 코드](https://developer.mozilla.org/ko/docs/Web/HTTP/Status) 
- 가령 음답으로 201이 나갔다는 것은 post 메소드의 요청이 들어왔다는것 (그렇다고 201이면 무조건 post 인것은 아님, 걍 대부분의 케이스)

## URL
- 리소스의 위치와 종류를 나타내는 주소
- 웹 상의 리소스를 식별하고 접근하기 위하여 사용
- http << 스키마/스킴(프로토콜) 즉 맨 앞에 http가 있으면 http 프로토콜을 사용하는것
- www.example.kr:80 << 도메인/호스트, 뒤에 붙는 숫자는 포트 
  - 포트는 일종의 게이트를 생각하면 된다. 80의 경우 디폴트이므로 생략하는 경우가 많다 
- 리소스 경로: /play
- 쿼리 스트링(문자열)과 경로 변수
  - 경로 매개변수 : 주소창의 경로 자체에 데이터 값을 넣는 방식(users/123/books/45)
  - 질의 매개변수 : url의 맨 끝에 ? 를 붙이고 key=value 형태로 나열하는 방식 (?category=it&sort=price&page=2))
